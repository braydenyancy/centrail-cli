# Centrail CLI 0.5.1 hotfix

## Why this release

The CLI was sending more parsed session data than Centrail needs. That could include local paths, host details, session identifiers, and Claude account information. Pairing also used the machine hostname as the device label.

Version 0.5.1 makes the upload boundary explicit. Usage uploads now contain only:

- request ID
- model name
- input, output, cache-read, and cache-write token counts
- timestamp

The CLI no longer uploads parser metadata, provider names, account details, local paths, hostnames, or platform details. Pairing uses the generic label `Centrail CLI`. Optional Git attribution remains limited to the documented repository basename, branch, commit SHA, and aggregate file/line counts.

This prevents new PII from being uploaded. It does not remove metadata or identities already stored by the server; historical cleanup is separate work.

## Reliability fixes

- Finds both direct Claude subagents and nested workflow subagents.
- Deduplicates Claude streaming snapshots by request ID and keeps the most complete usage record.
- Accepts current and future model names without a hard-coded allowlist.
- Triggers a one-time backfill when scanner behavior changes, so previously missed sessions are recovered automatically.
- Retains the worktree, Git environment, atomic state, overlapping-sync, and process-owned lock fixes from this PR.

Background collection, timers, hooks, and automatic assignment are intentionally deferred. This release is only the privacy and scanner hotfix.
